# Развёртывание на RelaxNet (relaxnet.pro / relaxdev.ru)

На RelaxNet диск контейнера не сохраняется между деплоями. Поэтому:

- **база** — PostgreSQL платформы (пользователи, балансы, презентации, настройки провайдеров);
- **файлы** (`/app_data`: картинки, загрузки, экспорты, шрифты, свои шаблоны) — копируются в
  Storage API платформы и возвращаются после деплоя. Как это устроено — ниже.

Порт: nginx слушает 80 и 8080, платформа шлёт трафик на 8080 — ничего настраивать не нужно.

## Шаги

1. **Проект.** «Добавить проект» → репозиторий `presenton-ru`, ветка `claude/i18n-ru`.
   Тип сборки — **Docker** (свой Dockerfile в корне). Первая сборка долгая (образ ~5 ГБ).
2. **База.** Вкладка «База данных» → создать PostgreSQL. `DATABASE_URL` пропишется сам.
3. **Хранилище.** Менеджер файлов → «API Доступ» → «Сгенерировать ключ». `STORAGE_API_KEY`
   пропишется сам — по нему включается копия файлов.
4. **Переменные** (вкладка «Переменные»):

   | Переменная | Значение | Зачем |
   |---|---|---|
   | `MIGRATE_DATABASE_ON_STARTUP` | `true` | миграции базы при старте |
   | `PRESENTON_PUBLIC_URL` | `https://<домен>` | адрес возврата после оплаты в ЮKassa и ссылки для MCP (без него берётся из заголовков запроса) |
   | `MEM0_ENABLED` | `false` | память чата ждёт локальную Ollama, её нет |
   | `APP_DATA_DIRECTORY` | `/app_data` | иначе платформа подставит заглушку (start.js её и так уберёт) |
   | `TEMP_DIRECTORY` | `/tmp/presenton` | то же |
   | `DISABLE_ANONYMOUS_TRACKING` | `true` | по желанию |

   Ключи ИИ-провайдеров, Студии (arckep) и ЮKassa удобнее задать после входа в
   «Настройки» — они хранятся в базе. Можно и переменными (`LLM`, `GOOGLE_API_KEY`,
   `STUDIO_API_KEY`, `YOOKASSA_SHOP_ID`, … — полный список в `docker-compose.yml`).
5. **Деплой.** После старта открыть адрес проекта, создать администратора.
6. **Домен.** Вкладка «Домены»: A-запись на адрес, который покажет панель.
7. **ЮKassa.** В кабинете ЮKassa — HTTP-уведомления на
   `https://<домен>/api/v1/billing/yookassa/webhook` (payment.succeeded, payment.canceled).

## Проверка после первого деплоя

1. Загрузить картинку в «Студии» или в презентацию.
2. Подождать 5–10 секунд, «Редеплой».
3. Картинка на месте, вход не слетел.

В логах при старте: `Storage sync on: N files known in the storage`, после загрузок —
`Storage sync: N uploaded`.

## Как работает копия файлов

`servers/fastapi/services/storage_sync/`.

- Локальная папка `/app_data` остаётся рабочей: код Presenton читает и пишет файлы как раньше.
- Каждые 3 секунды новые и изменённые файлы заливаются в хранилище (папка `app_data/`
  проекта), удалённые — удаляются. Соответствие «файл → объект в хранилище» лежит в таблице
  `storage_objects` (хранилище само добавляет к имени метку времени).
- При остановке контейнера несохранённое дозаливается (до 20 с, `STORAGE_SYNC_SHUTDOWN_TIMEOUT`).
- После старта: `userConfig.json` (в нём секрет, которым подписан вход) возвращается до запуска
  серверов, остальное — в фоне; файл, который понадобился раньше, скачивается в момент запроса.
  Файл, которого нет на новом диске, никогда не считается удалённым.
- Не копируются: `fastapi.db` (SQLite; на хостинге — PostgreSQL), `mem0/`, ассеты встроенных
  шаблонов (берутся из образа), временные файлы, файлы больше 5 ГБ.

Ограничения:

- Файлы в хранилище доступны по прямой CDN-ссылке. Presenton сам эти ссылки не показывает —
  файлы отдаются только через вход, а имена содержат случайные UUID. Когда у RelaxNet появится
  приватное хранилище, стоит перейти на него.
- Если хранилище недоступно во время деплоя, приложение стартует, недостающие файлы вернутся,
  когда оно оживёт (повтор раз в минуту), но вход у пользователей сбросится.
- Порт 1455 (вход Codex через OAuth) на платформе недоступен.

Настройки: `STORAGE_API_BASE_URL` (по умолчанию `https://relaxdev.ru/api/v1/storage`),
`STORAGE_SYNC_PREFIX` (папка в хранилище, `app_data`), `STORAGE_SYNC_INTERVAL` (секунды),
`STORAGE_SYNC_ENABLED=false` — выключить при заданном ключе.

## Проверка без RelaxNet

```bash
python scripts/e2e-stand/relaxnet_redeploy.py
```

Поднимает Presenton с PostgreSQL на порту 8080, без тома для `/app_data`, с заглушками в
переменных и поддельным Storage API, затем несколько раз удаляет контейнер и поднимает заново
(в том числе при недоступном CDN и недоступном хранилище) — 24 проверки.
