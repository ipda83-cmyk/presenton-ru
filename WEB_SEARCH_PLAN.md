# План: кастомизация веб-поиска — источники для ИИ

Ветка `claude/web-search-sources` (от `claude/i18n-ru`). Статус: **черновик плана, нужны решения из раздела 7**.

## 1. Задача

Администратор в админке ведёт список **источников**. У каждого источника есть:
- **адрес**: сайт, раздел сайта или конкретная страница;
- **описание**: что там лежит и когда это брать;
- **поисковик**: чем по нему искать.

Когда пользователь генерирует презентацию с веб-поиском, ИИ ищет факты, примеры, шаблоны и референсы **в этих источниках**, а не по всему интернету (или в первую очередь в них).

Пример источника:
| Поле | Значение |
|---|---|
| Название | Росстат — статистика |
| Адрес | `rosstat.gov.ru/statistics` |
| Описание | Официальная статистика РФ: население, экономика, цены. Брать для цифр и графиков. |
| Режим | Искать по разделу сайта |
| Поисковик | Как в настройках (авто) |

## 2. Как работает сейчас (Presenton 0.9.10)

- **Одна глобальная настройка** в «Настройки → Провайдер веб-поиска». Варианты:
  - «Авто» / «Встроенный поиск модели» — модель ищет сама; только OpenAI, Anthropic, Google;
  - внешние сервисы: SearXNG, Tavily, Exa, Brave (Serper есть в коде, но скрыт в интерфейсе).
- **Включается галочкой на каждую презентацию**, значение по умолчанию задаёт `WEB_GROUNDING`.
- **Где используется:**
  - Генерация плана (стандартный режим). Встроенный поиск: модель получает инструмент `web_search` и ищет сама. Внешний сервис: ИИ составляет **один** поисковый запрос, берутся **5 результатов**, только заголовок и короткий фрагмент, и они добавляются в промпт.
  - Умный режим: **один** запрос из темы и инструкций → результаты в контекст.
  - Чат-ассистент в редакторе поиском не пользуется (так задумано в коде).
- **Ограничения сейчас:**
  - нельзя указать сайты;
  - берутся только фрагменты, а не текст страниц;
  - ссылки на источники вырезаются, пользователь не видит, откуда взята информация;
  - один запрос на всю презентацию.
- **Код:**
  - `servers/fastapi/utils/web_search.py` — адаптеры поисковиков;
  - `utils/llm_calls/generate_web_search_query.py` — ИИ составляет запрос;
  - `utils/llm_calls/generate_presentation_outlines.py` — план;
  - `api/v1/ppt/endpoints/presentation.py` → `stream_smart_presentation` — умный режим;
  - `servers/nextjs/.../settings/WebSearchProvider.tsx` — настройки.
- Встроенный поиск модели идёт через библиотеку `llmai` 0.3.12, которая передаёт инструмент **без параметров**. Фильтр по сайтам придётся добавить самим: обёрткой или правкой вызова.

## 3. Что умеют поисковики (ограничение по сайтам)

| Поисковик | Только заданные сайты | Разделы (`site.ru/раздел`) | Лимит | Как |
|---|---|---|---|---|
| OpenAI, встроенный | да | нет, только домены (с поддоменами) | 100 доменов | `filters.allowed_domains`, только Responses API |
| Anthropic (Claude), встроенный | да (или «запрещённые сайты») | да | длинный список → ошибка `request_too_large` | `allowed_domains` / `blocked_domains`, не вместе |
| Google Gemini, встроенный | **нет** в Gemini API | — | — | подменяем внешним поисковиком (проверить в фазе 0) |
| Tavily | да, режимы «только» и «предпочитать» | домены | 300 / 150 | `include_domains`, `include_domains_mode: restrict / prefer` |
| Exa | да | да, и `*.поддомены` | 1200 | `includeDomains` / `excludeDomains`, может отдавать текст страниц |
| Serper (Google) | через `site:` в запросе | частично | длина запроса | `site:a.ru OR site:b.ru` |
| Brave | через `site:` в запросе | нет | длина запроса | параметра фильтра нет |
| SearXNG (свой сервер) | через `site:` в запросе | зависит от движков | длина запроса | удобен для РФ: без внешних ключей |
| **Чтение страницы** (наш сервер) | — | конкретный URL | — | скачиваем страницу и извлекаем текст, поисковик не нужен |

Вывод: для строгого поиска по сайтам лучше всего подходят **Tavily и Exa**, а из встроенных — **Anthropic и OpenAI**. Google и «простые» поисковики работают через `site:`, это менее надёжно.

## 4. Предлагаемое решение

### 4.1. Источник
| Поле | Зачем |
|---|---|
| Название | для людей |
| Адрес | сайт (`example.com`), раздел (`example.com/templates`) или страница (`https://example.com/page`) |
| Описание | **главное поле**: по нему ИИ решает, подходит ли источник теме |
| Режим | «Искать по сайту/разделу» или «Читать страницу целиком» |
| Тип материала | факты и статистика / тексты и примеры / шаблоны и структура / референсы (влияет на то, как ИИ использует найденное) |
| Поисковик | «как в настройках» или конкретный (Tavily, Exa, встроенный поиск модели…) |
| Приоритет, включён/выключен | порядок и быстрое отключение |
| Проверка | дата и результат последней проверки |

### 4.2. Наборы источников
Источники объединяются в **наборы**, например «Медицина», «Маркетинг», «Для вуза». У набора есть:
- **описание**;
- **строгость**:
  - «только источники набора»;
  - «сначала источники, потом весь интернет»;
- **поисковик по умолчанию** для своих источников;
- признак **«по умолчанию»** — набор, который используется, если пользователь ничего не выбрал.

Пользователь при создании презентации выбирает набор (рядом с галочкой веб-поиска) или оставляет «по умолчанию».

### 4.3. Как ИИ использует источники при генерации
1. **Отбор.** Если в наборе мало источников (до ~5), берём все. Если больше, модель по описаниям выбирает подходящие теме и для каждого составляет свой запрос. Это один короткий вызов со структурированным ответом.
2. **Поиск:**
   - «по сайту» — запросы с ограничением доменов через выбранный поисковик (см. таблицу в разделе 3);
   - «читать страницу» — скачиваем страницу (с кешем, лимитами размера и времени), извлекаем текст;
   - встроенный поиск модели получает список разрешённых сайтов прямо в инструменте.
3. **Контекст.** Найденное попадает в промпт плана и умного режима с пометками: название источника, его описание, URL, тип материала. Материал помечается как «справочный, недоверенный»: защита от инструкций внутри чужих страниц уже есть, её расширяем.
4. **Резерв.**
   - В режиме «сначала источники» при пустом результате ищем по всему интернету.
   - В строгом режиме продолжаем без веб-контекста и показываем предупреждение.
5. **Прозрачность:**
   - в статусе генерации: «Ищем на: rosstat.gov.ru, hse.ru…»;
   - список использованных источников — в заметках спикера (или на последнем слайде, см. Р6).

### 4.4. «Чем искать» (нейросети и поисковики)
Для набора или отдельного источника выбирается:
- **Встроенный поиск модели** (OpenAI, Anthropic): модель сама ищет и читает. Работает, только если генерация идёт на этой же модели.
- **Внешний поисковик** (Tavily, Exa, Serper, Brave, SearXNG): работает с любой моделью. Tavily и Exa надёжнее ограничивают поиск сайтами и умеют отдавать текст страниц.
- **Авто:** если текущая модель умеет фильтр по сайтам — встроенный поиск, иначе первый настроенный внешний. Если ничего не подходит, админка заранее показывает предупреждение.

### 4.5. Админка
Новый раздел «Источники поиска» (виден только администраторам, рядом с «Пользователями» и «Ключами API»):
- таблица источников: название, адрес, режим, набор, поисковик, вкл/выкл, последняя проверка;
- форма добавления и редактирования. Адрес нормализуется автоматически: `https://www.Example.com/Templates/` → `example.com/templates`;
- кнопка **«Проверить»**: пробный поиск или загрузка страницы, показывает 3–5 найденных результатов;
- управление наборами: создать, описать, выбрать строгость и набор по умолчанию;
- общие лимиты: сколько источников и запросов на одну генерацию, сколько результатов на запрос;
- (позже) импорт и экспорт списка в CSV/JSON;
- весь интерфейс — на RU/EN по той же схеме, что и локализация.

### 4.6. Данные и API (для разработчика)
- **Таблицы:**
  - `web_source_collection`: id, name, description, strictness, default_engine, is_default, timestamps;
  - `web_source`: id, collection_id, name, url, host, path_prefix, description, mode, material_type, engine, priority, enabled, last_checked_at, last_check_status, created_by, timestamps.
  - Миграция Alembic, работает на SQLite и PostgreSQL (для relaxdev).
- **Презентация:** поле `web_source_collection_id` (nullable), чтобы перегенерация шла по тому же набору.
- **API:**
  - `GET/POST/PUT/DELETE /api/v1/admin/web-sources…` и `…/collections…` — только админ;
  - `POST /api/v1/admin/web-sources/{id}/test` — проверка источника;
  - `GET /api/v1/web-source-collections` — список наборов для формы создания (без служебных полей).
- **Бэкенд:**
  - адаптеры поисковиков получают `include_domains`, а для Serper, Brave и SearXNG — сборку `site:`;
  - обёртка встроенного `web_search` для OpenAI и Anthropic передаёт домены;
  - модуль «читать страницу» с защитой (раздел 5);
  - кеш результатов на время генерации.
- **Тесты:**
  - строгий режим не пропускает чужие домены — на каждом адаптере;
  - нормализация адресов;
  - права: не-админ получает 403;
  - миграции;
  - сквозной прогон на стенде.

### 4.7. Где подключается в пайплайне
| Этап | Сейчас | Станет |
|---|---|---|
| План (стандартный режим) | 1 запрос → 5 фрагментов | отбор источников → запросы по ним → фрагменты или тексты с пометками источника |
| Умный режим | 1 запрос | то же, что для плана |
| Слайды | поиска нет | без изменений (материал уже в плане) |
| Чат-ассистент | поиска нет | вне этого этапа (можно позже: «найди на наших источниках») |

## 5. Безопасность, деньги, окружение
- **Права:** источники меняет только администратор; обычные пользователи видят только названия и описания наборов.
- **«Читать страницу»:**
  - только `http(s)`;
  - запрет внутренних адресов (localhost, 10.x, 192.168.x, метаданные облака — защита от SSRF);
  - лимит размера (например 5 МБ) и времени (15 с);
  - только HTML, PDF, текст;
  - редиректы проверяются по тем же правилам.
- **Недоверенный контент:** тексты с чужих сайтов — «справочный материал», не инструкции. Скрипты и разметка вырезаются.
- **Деньги:**
  - встроенный поиск Anthropic — $10 за 1000 поисков плюс токены;
  - Tavily и Exa — по кредитам;
  - нужны лимиты запросов на генерацию и журнал поисков для админа.
- **relaxdev (РФ):** внешние поисковики и встроенный поиск западных моделей пойдут через прокси платформы (`RELAXDEV_PROXY_URL`). Доступ проверяем в фазе 0. Вариант без внешних сервисов — свой SearXNG или только режим «читать страницу».

| Фаза | Что делаем | Результат | Объём |
|---|---|---|---|

| 1. Данные и API | таблицы, миграция, CRUD для админа, нормализация адресов, тесты | API источников и наборов | M |
| 2. Админка | раздел «Источники поиска», формы, «Проверить», наборы, RU/EN | админ сам ведёт источники | M |
| 3. Поиск по источникам | фильтры доменов во всех адаптерах, обёртка встроенного поиска, «читать страницу» с защитой, кеш | поиск ограничивается заданными сайтами | L |
| 4. Встраивание в генерацию | отбор источников по описаниям, стандартный и умный режимы, выбор набора при создании, статусы | генерация реально использует источники | M |
| 5. Прозрачность и контроль | источники в заметках спикера, журнал поисков, лимиты и расходы | видно, откуда информация и сколько стоит | S–M |

| Р7 | Какими поисковиками реально пользуемся на relaxdev | Tavily / Exa / встроенный поиск / свой SearXNG | решаем после проверки доступа в фазе 0 |

## 8. Критерии готовности
- Администратор добавляет источник меньше чем за минуту, «Проверить» показывает реальные результаты.
- В строгом режиме все найденные материалы — только с сайтов набора (автотест на каждый поисковик).
- Генерация с набором работает на OpenAI, Anthropic и Google (Google — через внешний поисковик), в стандартном и умном режиме.
- Пользователь видит, какие источники использованы.
- Интерфейс и ошибки на RU/EN; миграция на SQLite и PostgreSQL; тесты бэкенда и фронта зелёные.
