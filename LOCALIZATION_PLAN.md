# План локализации Presenton (RU/EN)

**Проект:** Presenton — open-source генератор презентаций на ИИ (версия `0.9.10-beta`).
**Задача:** локализовать интерфейс на русский язык (русский по умолчанию, английский — переключателем).
**Дата:** 2026-09-19.
**Статус:** план согласован (заказчик + Денис), приступаем к реализации.

---

## 1. Кратко (TL;DR)

- Сейчас у Presenton **интерфейс только на английском** и **никакой инфраструктуры перевода нет** — все надписи зашиты в код напрямую.
- Заводим систему интернационализации (**next-intl v4**, официально поддерживает Next.js 16), выносим все тексты в языковые файлы `messages/ru.json` и `messages/en.json`, добавляем **переключатель языка** и делаем **русский языком по умолчанию**.
- Язык интерфейса **не влияет** на язык самих презентаций — за язык слайдов уже отвечает отдельный селектор (`LanguageSelector`), его не трогаем.
- Выбор языка запоминается **в профиле пользователя** (по просьбе Дениса) и в cookie как запасной вариант.
- Переводим и фронтенд, и **пользовательские тексты ошибок бэкенда** (FastAPI).
- Работаем **фазами**: сначала основной пользовательский поток, затем кабинет и админка, в конце — вычитка и сборка. Каждая фаза собирается и проверяется в Docker.
- Всё ведётся в **git-ветке** — Денис получит доступ к репозиторию и увидит изменения отдельным чистым слоем.

| Часть | Технологии | Роль |

## 3. Важное различие: язык интерфейса ≠ язык презентации

В Presenton уже есть выбор языка **для генерируемой презентации** (компонент `app/(presentation-generator)/upload/components/LanguageSelector.tsx` — на каком языке ИИ пишет слайды). Это **отдельная** сущность.

Мы добавляем **язык интерфейса** (кнопки, меню, подписи, диалоги). Это два независимых параметра:
- Можно смотреть интерфейс на русском и генерировать презентацию на английском — и наоборот.
- Существующий селектор языка презентации **сохраняем как есть** (только переведём его собственные подписи вроде «Select language»).

## 4. Технический подход

### 4.1. Библиотека
**next-intl v4.4+** — де-факто стандарт i18n для Next.js App Router, официально поддерживает Next.js 16. Тот же инструмент уже отработан на другом проекте.

> Известный нюанс: директива Next.js 16 `use cache` пока не дружит с next-intl. Presenton её не использует, так что нас это не затрагивает.

### 4.2. Маршрутизация языка
**Без языкового префикса в URL** (согласовано). Плюсы: адреса остаются чистыми (одна ссылка на страницу), меньше правок в маршрутизации, что важно при 400+ файлах. По умолчанию — русский.

### 4.3. Где хранится выбор языка
Согласовано с Денисом — язык запоминается **и в профиле пользователя, и в cookie**:
- **профиль пользователя** — для залогиненных: выбор сохраняется на сервере и подтягивается на любом устройстве;
- **cookie `NEXT_LOCALE`** — работает всегда, в т.ч. для анонимных сессий и режима без авторизации.

Порядок определения языка: **профиль (если пользователь вошёл) → cookie → русский по умолчанию.**

> Для хранения в профиле нужна небольшая доработка бэкенда: поле языка в модели пользователя (`users`) + **миграция Alembic** + маленький эндпоинт для сохранения. Presenton применяет миграции автоматически при старте, поэтому на деплое дополнительных ручных шагов быть не должно (сверю при реализации).

### 4.4. Что добавляем (новые файлы)
```
servers/nextjs/
├── i18n/
│   ├── config.ts          # список локалей ["ru","en"], defaultLocale "ru"
│   └── request.ts         # определение локали (профиль/cookie), подгрузка messages/*.json
├── messages/
│   ├── ru.json            # русские тексты (основной язык)
│   └── en.json            # английские тексты (исходные строки Presenton)
├── components/
│   └── LanguageSwitcher.tsx   # переключатель RU/EN
└── app/
    └── actions/locale.ts  # server action: сохранить выбор (cookie + профиль)
```

### 4.5. Что правим (существующие файлы)
- `next.config.mjs` — оборачиваем конфиг плагином `createNextIntlPlugin`.
- `app/layout.tsx` — динамический `<html lang={locale}>`, оборачиваем приложение в `NextIntlClientProvider`.
- Модель пользователя + миграция (для языка в профиле), небольшой эндпоинт сохранения.
- Каждый компонент с текстом — заменяем зашитые строки на ключи перевода (`useTranslations()` в клиентских компонентах, `getTranslations()` в серверных).

### 4.6. Формат текстов
Тексты — в JSON по «неймспейсам» (разделам), с поддержкой подстановок и множественного числа (ICU MessageFormat). Пример:
```json
// messages/ru.json
{
  "upload": {
    "title": "Создать презентацию",
    "slidesCount": "{count, plural, one {# слайд} few {# слайда} many {# слайдов} other {# слайда}}"
  }
}
```

## 5. Фазы работ

Каждая фаза = самостоятельный, собираемый результат. После каждой — сборка и проверка в Docker (на этой машине нет Node напрямую, поэтому сборка идёт в контейнере).

### Фаза 0 — Инфраструктура
Установка next-intl, каркас (`i18n/`, провайдер, `next.config.mjs`, динамический `lang`), пустые `messages/*.json`, переключатель языка, сохранение выбора (cookie + профиль).
**Результат:** приложение собирается, переключатель работает (пока тексты английские).

### Фаза 1 — Ядро пользовательского потока
Онбординг (`OnBoarding/*`) → `upload` (создание) → `outline` (план) → `presentation` (редактор слайдов) → экспорт; плюс общие UI-компоненты (кнопки, диалоги, тосты).
**Результат:** основной сценарий «создал → отредактировал → выгрузил» полностью на русском.

### Фаза 2 — Личный кабинет и настройки
`dashboard`, `settings`, `templates`, `custom-template`, `documents-preview`.

### Фаза 3 — Остальное + бэкенд
`community`, `admin`, экспортные экраны (`pdf-maker`), редкие диалоги, а также **пользовательские тексты ошибок/уведомлений FastAPI** (по решению Дениса).

### Фаза 4 — QA и вычитка
Сверка полноты (ключей в RU и EN поровну), проверка ICU-разметки, финальная сборка, вычитка русского на «живость» (не машинный перевод), клик-тест по всем экранам. Сверка с требованиями площадки relaxdev.ru.

## 6. Контроль качества

- **Полнота:** количество и состав ключей в `ru.json` и `en.json` совпадают (автоматическая сверка).
- **Сборка:** `next build` проходит без ошибок в Docker.
- **Рантайм:** нет ошибок next-intl (missing message и т.п.) в консоли на всех экранах.
- **Клик-тест:** ручной проход по каждому экрану на RU и EN.
- **Вычитка:** русский — живой и терминологически корректный (перевод делаю я, не автоперевод).

## 7. Что НЕ входит в объём

- Контент презентаций и шаблоны слайдов (`templates/`, `layouts.json`) — это пользовательские данные, не интерфейс.
- Язык генерации слайдов ИИ — уже управляется существующим селектором.
- Внутренние промпты ИИ и системные логи бэкенда (пользователь их не видит). **Пользовательские** тексты ошибок/уведомлений FastAPI — **входят** в объём (Фаза 3).
- **Десктоп-обёртка Electron** (`electron/`): это упаковка Presenton в устанавливаемое **десктоп-приложение** (Windows/Mac/Linux). Деплой планируется на relaxdev.ru как **веб** — поэтому десктоп-версию не локализуем. При необходимости русифицировать её позже — та же система переводов, нужна лишь пересборка Electron-пакета.
- Добавление языков сверх RU/EN — архитектура это позволит, но в этот объём не входит.

## 8. Риски и как их снимаем

| Риск | Как снимаем |
|---|---|
| Next.js 16 очень свежий | next-intl v4.4 его официально поддерживает; проверяем сборкой на каждой фазе |
| Большой объём (423 файла) | фазовый подход, начинаем с самого важного; каждая фаза — рабочий результат |
| Компоненты рендера слайдов рядом с UI | аккуратно разделяем: переводим только элементы интерфейса, не контент |
| Обновление Presenton в будущем перезатрёт правки | все изменения в git-ветке отдельным слоем → легко перенести/смёржить при апдейте |
| Миграция БД на деплое | миграция крошечная (одно поле), применяется автоматически при старте; сверим на relaxdev |

## 9. Как Денису это ревьюить и катить

- **Версионирование:** инициализирован git-репозиторий, работа ведётся в ветке `claude/i18n-ru` поверх чистого базового коммита Presenton. Сдача — **доступ к git-репозиторию** (выбор Дениса): выложим репозиторий, Денис получит доступ и увидит все изменения отдельным слоем.
- **Деплой:** relaxdev.ru (док: https://relaxdev.ru/docs). На код не влияет; сверимся с требованиями площадки на финальной проверке (Фаза 4).
- **Сборка:** штатная, через `Dockerfile` / `docker-compose.yml` Presenton — наши изменения не меняют процесс сборки, только добавляют зависимость `next-intl`.
- **Миграции БД:** **не нужны.** Язык профиля хранится в существующей таблице key/value (`ui_locale:<id пользователя>`), а не новой колонкой: модель пользователя читается на каждый запрос, и колонка без накатанной миграции сломала бы вход. Для анонимных/без-авторизации сессий язык живёт в cookie.
- **Откат:** тривиальный — откат ветки, upstream Presenton не тронут.

## 12. Статус выполнения (23.09.2026)

Все фазы выполнены, ветка `claude/i18n-ru`.

- **Фронтенд:** весь интерфейс на next-intl, каталоги `messages/ru.json` / `en.json` (≈2370 ключей, наборы совпадают). Язык в cookie `NEXT_LOCALE`, переключатель в шапке; метаданные страниц, даты и числа — по языку интерфейса.
- **Немодульный код (сервисы API, утилиты):** `utils/clientI18n.ts` — `tr(key, английский_фолбэк)`, мост регистрируется только в браузере.
- **Демо-контент в слайдах** (вставляемые таблицы/графики/инфографика, «Новый пункт» и т.п.) идёт на **языке презентации** (решение заказчика): `components/slide-editor/content/demoContent.ts`.
- **Бэкенд:** `utils/i18n` (middleware локали: `X-Locale` → cookie → ru), каталоги `utils/i18n/{en,ru}.py` + `errors_{en,ru}.py`; все пользовательские `HTTPException` (~290 мест), ошибки провайдеров, валидация 422. Исключение: тексты внутри попыток smart-генерации остаются английскими — это обратная связь для модели.
- **Язык в профиле (Д3):** при входе cookie выставляется из профиля, переключатель сохраняет выбор (`PUT /api/v1/auth/locale`); порядок профиль → cookie → ru.
- **Остаётся английским намеренно:** названия встроенных шаблонов (бренды), описания блоков внутри шаблонов (данные шаблонов), аналитика (Mixpanel), промпты модели.

**Как проверить:** `servers/fastapi`: `pytest tests` (1220 тестов, в т.ч. `tests/unit/test_i18n.py` — паритет каталогов и наличие каждого ключа из кода, `tests/integration/test_user_locale.py`). `servers/nextjs`: `next build`, `node --test` (57), Cypress component (3). Переключение: кнопки RU/EN в шапке; для API — заголовок `X-Locale: en`.
